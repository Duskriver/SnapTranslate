# 翻译关窗后待机内存优化

将截图、PNG 编码、网络请求和结果浮窗一起放到临时工作进程中，关窗即退出。主进程继续管理菜单栏、热键、框选、设置和钥匙串。基准中，翻译后的主进程待机占用中位数由 **23.89 MiB 降至 14.52 MiB**，新版冷启动为 **13.36 MiB**。

## 同轮对照

2026-10-23，Apple Silicon，macOS 27.0.1（26A434），Swift 6.4，`swiftc -O -swift-version 6`。旧版源码来自 `8867c76`，新版为本轮工作区快照；相同签名身份和应用标识。每版 3 个新进程，每进程 5 轮，交替执行顺序：旧/新、新/旧、旧/新。

测试真实执行 AppDelegate、区域选择的进程内鼠标事件、ScreenCaptureKit 截图、ImageIO PNG 编码、URLSession HTTP 上传、SSE 解析、结果控件显示与关闭。固定测试窗口仅含公开英文句子；服务端为 loopback 上的固定 SSE 响应，使用公开占位密钥，不读取用户凭据，不访问 DeepSeek。生产地址、模型、提示词、画质和输出上限保持不变。

框选 870×470 点，当前显示器 backing scale 为 2；新旧 30 次上传均为 1740×940 像素、73,207 字节的 PNG，SHA-256 全部相同：`60487d35ab1031519dcc7c27736ec31f3fe874eac4f51e9157966cbf48802627`。服务只保存这些长度、尺寸和哈希，不保存截图。

旧版直接检查真实结果窗口的“翻译完成”再关闭；新版只在忽略目录中的源码副本里插入成功后自动关闭工作窗口，错误则使该轮失败。主程序入口也仅在副本中加入基准驱动。每轮等待主任务及工作进程退出，再等 3 秒采样；第 5 轮采样后另等 5 秒，最后一次采样距关窗约 8 秒。没有使用 AX 或外部界面截图查询被测窗口，没有主动清缓存或制造系统内存压力。

| 指标（3 个进程的中位数） | 旧版 | 新版 |
| --- | ---: | ---: |
| 冷启动主进程 | 13.13 MiB | 13.36 MiB |
| 第 5 轮关窗后主进程 | 24.02 MiB | 14.58 MiB |
| 再静置 5 秒 | 23.89 MiB | 14.52 MiB |
| 待机值相对各自冷启动的增加 | 10.77 MiB | 1.16 MiB |

最终待机值范围为旧版 23.81–23.91 MiB、新版 14.47–14.53 MiB。全部 15 轮关窗后的当前占用范围为旧版 23.75–25.16 MiB、新版 14.41–14.63 MiB。最终待机中位数减少约 **9.38 MiB（39.2%）**；不将旧测试中 UI 自动化后的约 31 MiB 与本轮数值计算收益。

## 代价与资源范围

- 本地流程耗时中位数为旧版 90.78 ms、新版 278.26 ms，增加约 187 ms；范围分别为 85.63–166.36、252.13–338.66 ms。新版还包含工作进程启动、浮窗关闭和进程退出回收。这是本地固定响应测试，不能用于承诺真实 API 的固定延迟。
- 翻译期间最多一个工作进程，上一进程退出并回收后才启动下一进程。每组最后的采样均无存活子进程，窗口关闭后不保留工作进程。
- 外部观察器约每 100 ms 用 `proc_pid_rusage` 读取主进程和直接子进程的当前 physical footprint。两者相加的采样最大值中位数为旧版 25.66 MiB、新版 38.24 MiB，新版范围 37.03–38.70 MiB。**翻译期间的进程占用之和增加了**。该和未去重共享页，采样也可能漏掉短暂峰值，且不包含 XPC、WindowServer、GPU、测试窗口和服务端，不能当作整机新增物理内存或严格峰值。
- 此次优化针对翻译路径；主动打开主进程的设置窗口或执行 AX 查询仍可初始化其他 AppKit 缓存，不保证任意操作后都回到冷启动值，也不保证不同 macOS、显示器和选区下有相同数值。

## 生命周期和验证

主进程通过匿名管道发送选区、语言和本次密钥，参数列表不含密钥。工作进程不读钥匙串、不存截图或译文；截图同时排除主进程和工作进程的窗口。关窗、快速重拍和退出会终止旧任务，阻止迟到事件影响新任务；父进程异常退出时，工作进程也监听其退出并结束。工作进程未能启动或异常中止时，主进程提供错误浮窗兜底。

`swift test` **75 项通过**（TranslationCore 23、应用 52，参数化场景另展开），包括消息分块、UTF-8、类型化错误、消息长度与截断、进程启动失败、取消后终止及回收、取消排队任务、窗口动作转发、旧请求动作隔离和启动失败兜底。Release 打包与签名身份验证通过；保留现有钥匙串 API 弃用警告。

最终正式签名构建另完成一次真实 DeepSeek 调用：用户在系统弹窗中授权读取已保存密钥，并确认浮窗显示「翻译完成」和译文后手动关闭。随后检查确认翻译工作进程（PID 12962）及其 `SetStoreUpdateService`（PID 12963）均已退出，主进程仍运行。本次界面检查还打开过主进程设置并触发 AX，关窗后的主进程为 26.0 MiB，不能拿来验证无界面观察条件下的 14.52 MiB；这里验证的是实际 API 翻译成功和关窗后的进程回收。结束界面检查并重启同一构建后，主进程冷启动待机为 13.7 MiB，关联 SetStore 为 2.453 MiB，无翻译子进程、ThemeWidget 或自动填充服务。后者是重启后的快照，不能当作真实翻译后回落的测量。只读检查输出保留在 `build/idle-worker-validation/live-after-close.json` 和 `final-idle.json`。

原始数据见 [逐阶段 CSV](2026-10-23-idle-worker.csv)、[主/子进程观察摘要](2026-10-23-idle-worker-observations.json)。本机完整快照、上传哈希和采样记录位于忽略目录 `build/idle-memory-comparison.SoP5Rt/`。

早期一次 2 秒间隔试跑在旧版第 5 次截图阶段失败（服务器只收到 4 张图），该次已中止，未计入统计，未能确定系统捕获失败原因。随后驱动增加错误详情，并使用上述 3 秒间隔，完整 3 组对照均成功。另有一次读取真实钥匙串的诊断运行被系统授权阻塞，终止后改用本基准的占位密钥和本地响应。
